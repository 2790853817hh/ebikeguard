# 跨对话记忆交接指南

> 适用场景：单个对话上下文快满、或想为一个新主题另开对话，但希望新对话"记得"之前的事。
> 核心结论：**新对话不会自动知道旧对话的内容，记忆靠文件传递，不靠模型记性。**

---

## 一、机制：信息存在哪三层

| 层 | 物理位置 | 存什么 | 谁写 | 新对话怎么拿到 |
|---|---|---|---|---|
| ① 云端记忆 | 服务端（按账号） | 用户画像、跨会话要点 | 服务端自动提炼 | 开场自动注入，无需操作 |
| ② 用户级记忆 | `C:\Users\cg\.workbuddy\user-<ID>\MEMORY.md` | 跨项目长期偏好、本机环境硬规则 | 你要求 → AI 写入 | 同机同账号开场自动注入 |
| ③ 工作空间记忆 | `<项目>\.workbuddy\memory\MEMORY.md` 与 `YYYY-MM-DD.md` | 项目内决策、强制约束、进度、已知坑 | 你 / AI 随手追加 | **需显式说一句"先读记忆"最稳** |

判断标准，一句话：
- **换个项目也要遵守的** → 写 ②（如"命令一律 PowerShell"）
- **只对某个项目成立的** → 写 ③（如"状态流转唯一入口是 apply_transition()"）
- **不用管，系统自己会记住的** → 留 ①

---

## 二、三步操作法

### 第 1 步 · 收尾：让旧对话产出交接简报

在旧对话里直接说（可复制）：

```
这次对话快到头了。请做三件事：
1. 把关键结论固化进 .workbuddy/memory/MEMORY.md 的相应章节（没有的章节就新增）；
2. 在今天的 .workbuddy/memory/<今天日期>.md 追加一条简短记录；
3. 按 docs/跨对话记忆交接指南.md 的模板，产出一份交接简报，
   写到 .workbuddy/memory/HANDOFF-<主题>-<日期>.md。
只写有长期价值的内容，不要复述聊天过程。
```

### 第 2 步 · 落盘：确认文件真的写进去了

- 让 AI 回显文件路径，或自己打开 `.workbuddy\memory\` 看一眼。
- **不落盘 = 没记忆**。这一步是整条链路的唯一硬依赖。

### 第 3 步 · 开场：让新对话先读再干

在新对话的第一条消息里带上（可复制）：

```
先读 E:\cg\Documents\WorkBuddy\电动车识别\.workbuddy\memory\MEMORY.md
和最近两天的日志，以及 .workbuddy\memory\HANDOFF-*.md（如有）。
以文件内容为唯一背景，读完再动手。
```

同工作空间内，这一句通常就够了——③ 层文件就是为跨对话复用设计的。

## 三、分场景速查

| 场景 | 做法 |
|---|---|
| 同一项目，只是上下文满了 | 收尾落盘 → 新对话开场说"先读记忆"。**不用手抄简报。** |
| 同一项目，但要换新主题 | 只继承"强制约束 + 与该主题相关的决策"，不搬无关细节。落盘时把章节分开写，便于按需读。 |
| 换到另一个项目 | 靠 ② 用户级记忆自然继承通用偏好；项目相关内容靠手粘交接简报。 |
| 只想找回某次聊过的细节 | 让 AI 检索历史对话（描述清"找什么 + 大概什么时候"），比翻文件快。 |
| 跨设备 | ① 跟着账号走；② ③ 是本地文件，需手动同步或粘贴简报。 |

## 五、三条经验

1. **落盘要及时**。别等上下文真满了才想起写——那时往往已经来不及把细节说清。每个阶段性节点就追加一条。
2. **写得"抗遗忘"**。写结论和理由，不写过程；写"为什么不用 B 方案"，比写"我们讨论了 B 方案"有用一百倍。
3. **③ 只增不改**。日志文件是追加式的，历史记录不要覆盖；要修正结论就在 `MEMORY.md` 里改，日志留痕。
