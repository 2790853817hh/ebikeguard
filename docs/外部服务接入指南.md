# 外部服务接入指南

本文回答一个问题：**那几类需要从外部获取的东西，具体怎么操作、填到哪里、怎么验证。**

先说结论——**没有它们系统也能完整跑通全流程**，因为它们都有本地兜底。差别只在「能不能上生产」：

| 项目                | 是否生产必需 | 不配的后果                                                             | 本地兜底                 |
| ----------------- | ------ | ----------------------------------------------------------------- | -------------------- |
| **短信（阿里云短信认证）**   | **必需** | 上报人收不到验证码，**无法登录上报**                                              | Mock 通道，验证码写日志并由接口回显 |
| **域名 + HTTPS 证书** | **必需** | 手机浏览器拿不到相机与定位权限（`getUserMedia`/`Geolocation` 要求安全上下文），拍照上报在真机上不可用 | HTTP 在电脑端可用          |
| **高德地图 Key**      | 建议     | 只存经纬度，地址需上报人手工填写                                                  | Stub 解析器，不外呼         |
| **阿里云 OSS**       | 可选     | 图片存本地磁盘，占用服务器磁盘、无法多机共享                                            | 本地磁盘分桶存储             |
| **视觉大模型 API-KEY** | P1 阶段  | AI 初审仍为规则占位引擎                                                     | 规则引擎，零依赖可解释          |

> 建议顺序：**先短信 → 再域名证书 →（同时）高德 Key → 最后按容量决定是否上 OSS**。

## 零′ 命令怎么敲（先看这个，能省掉一整类报错）

**本文所有本机命令一律使用 PowerShell 写法**（本机默认终端是 PowerShell 7）。统一格式就两步：

```powershell
cd "E:\cg\Documents\WorkBuddy\电动车识别"
.\.venv\Scripts\python.exe scripts\check_external.py --probe
```

四个要点：

1. **先 `cd` 到项目根目录** —— 脚本里用的是相对路径，不在根目录会找不到文件；
2. **`.\.venv\Scripts\python.exe` 必须带 `.exe`** —— PowerShell 不会给显式路径自动补扩展名，  
   写 `./.venv/Scripts/python`（bash 风格，连斜杠方向都不对）会报  
   「术语 './.venv/Scripts/python' 不会被识别为 cmdlet、函数、脚本文件或可执行程序的名称」；
3. **路径用反斜杠**（`\`），虽然 PowerShell 也接受 `/`，但混用容易看错；
4. **不要用 `\` 折行** —— 那是 bash 的续行符，PowerShell 会把整行当一条命令，报  
   「一元运算符 '--' 后缺少表达式」。参数多就写成一整行。

**需要清空代理变量时**（本机环境注入了 `HTTP_PROXY`/`HTTPS_PROXY`，pip 会连不上源）：

```powershell
$env:HTTP_PROXY=""; $env:HTTPS_PROXY=""; $env:ALL_PROXY=""
```

**例外：服务器上的命令仍是 bash**。第二节 Nginx / 证书、第九节运维脚本都跑在阿里云 Linux 上，  
那些命令保持 `sudo` + `/etc/nginx/...` 的 Linux 形式，**不要**在 Windows 里执行。

**速查对照**

| 场景           | PowerShell（本项目统一用这个）                      | bash（仅服务器 / 备查）                |
| ------------ | ----------------------------------------- | ------------------------------ |
| 调虚拟环境 python | `.\.venv\Scripts\python.exe`              | `./.venv/Scripts/python`       |
| 复制文件         | `Copy-Item a b`                           | `cp a b`                       |
| 路径分隔符        | `\`                                       | `/`                            |
| 连接多条命令       | `;`                                       | `&&` 或 `;`                     |
| 命令折行         | 不支持，写成一整行                                 | 行尾 `\`                         |
| 清空代理变量       | `$env:HTTP_PROXY=""; $env:HTTPS_PROXY=""` | `unset HTTP_PROXY HTTPS_PROXY` |

**结论**：个人开发、开发联调一律用通道 A；等拿到单位资质、且确实需要短信通知时再切通道 B。


### 1.1 通道 A：阿里云短信认证服务（`aliyun_dypns`）

**① 开通服务**  
控制台搜「号码认证服务」→ 开通 → 进入「短信认证」。个人实名认证即可，**无需企业营业执照**。  
控制台入口：<https://dypns.console.aliyun.com>

**② 选定赠送的签名与模板（这是免资质的核心）**

- 打开「赠送签名配置」<https://dypns.console.aliyun.com/smsCertParamsConfig/sign> → 选定要下发的签名，记下**签名名称** → 填 `SMS_SIGN_NAME`；
- 打开「赠送模板配置」<https://dypns.console.aliyun.com/smsCertParamsConfig/template> → 选定验证码模板，记下**模板编号**（形如 `100001`）→ 填 `SMS_TEMPLATE_CODE`；
- 赠送签名必须搭配赠送模板使用，**不可自定义签名**；
- 模板里的验证码变量名通常就是 `code`，如与模板不一致，改 `SMS_TEMPLATE_PARAM_NAME`；模板若还含 `${min}` 之类的变量，用 `SMS_TEMPLATE_EXTRA_JSON` 补固定值，例如 `{"min":"5"}`。

**③ 创建 AccessKey（RAM 子账号 + 最小权限，不要在根账号上创建）**

1. 控制台搜「RAM 访问控制」→ 身份管理 → 用户 → **创建用户**；
2. 登录名称如 `ev-audit-sms`，访问方式勾选 **OpenAPI 调用访问**（不要勾控制台登录）；
3. 创建成功后进入「保存结果」页 —— **先点右侧两个「复制」，把 AccessKey ID 与 Secret 存进密码管理器**。  
   ⚠️ 页面关闭后控制台**再也查不到 Secret**（提示原文：「页面关闭后没有任何方式再次查询 AccessKey Secret」），  
   只能删除该 AccessKey 重新创建。截图存档不算保存，图片里的 Secret 是打码的。  
   **补救办法**（页面已关掉时）：RAM → 身份管理 → 用户 → 点进 `ev-audit-sms` → 「认证管理」页签 →  
   创建 AccessKey，会重新给一次 Secret（同时建议删除旧的、已丢失的那一个）。
4. 点「返回」回到用户列表，开始授权。**两条路选一条**：

   **路线 A —— 省事（官方口径的"最小权限"）**

   先点「返回」离开「保存结果」页，回到**用户列表**。然后：
   1. 在表格里**勾选** `ev-audit-sms` 这一行最左边的复选框  
      —— ⚠️ 没勾选时，表格上方那个 **「添加权限」是灰色、点不动的**（它和「添加到用户组」并排，在工具条最右侧），  
      这是最容易卡住的地方；
   2. 勾选后「添加权限」变为可点，点它 → 弹窗中选「系统策略」→ 搜索框输入 `AliyunDypnsFullAccess` → 勾选 → 确定。
   > 备选入口（勾选框找不到时用这条）：点用户名 `ev-audit-sms` 进入**用户详情页** →  
   > 「权限管理」页签 → **「新增授权」** → 选「系统策略」→ 搜索 `AliyunDypnsFullAccess` → 勾选 → 确定。  
   > 官方文档《自定义权限策略参考》明确写着：「**短信认证服务所需的最小权限策略为 `AliyunDypnsFullAccess`**」——  
   > 因为号码认证服务只提供这一个产品级系统策略（内容为 `dypns:*`），没有更细粒度的系统策略可选。  
   > 另有只读策略 `AliyunDypnsReadOnlyAccess`，本项目不需要。  
   > **路线 B —— 严格最小权限（只给发验证码这一个动作）**
   1. 左侧「权限管理 → 权限策略」→ **创建权限策略** → 选「脚本编辑（JSON）」→ 粘贴下面内容 →  
      策略名称填 `ev-audit-sms-send` → 确定；
   2. 回「身份管理 → 用户」，同样**先勾选该用户**，再点「添加权限」→ 选「自定义策略」→  
      勾选 `ev-audit-sms-send` → 确定。

```json
{
  "Version": "1",
  "Statement": [{"Effect": "Allow", "Action": ["dypns:SendSmsVerifyCode"], "Resource": ["*"]}]
}
```

> `Resource` 必须写 `*`：号码认证服务的该接口不支持资源级授权（官方 API 文档标注为「全部资源」），  
> 写具体资源 ARN 会导致授权无效。

**两个常见坑**

- **权限不互通**：国内短信服务权限（`AliyunDysmsFullAccess`）与号码认证服务权限（`AliyunDypnsFullAccess`）  
  是两套。只授了短信服务权限的 RAM 用户调 dypns 接口会返回 403 / `isv.RAM_PERMISSION_DENY`。
- **授权即时生效**，不需要等待；用户列表里「控制台访问：没有设置」是正常的（我们只要 OpenAPI 调用）。

**⑤ 填写 `.env`**

只有 4 个值需要你从控制台抄过来，其余保持默认即可：

| 配置项                            | 值从哪儿来                                   | 形态                                |
| ------------------------------ | --------------------------------------- | --------------------------------- |
| `SMS_ACCESS_KEY_ID`            | RAM「创建用户」成功页 → AccessKey ID 右侧**复制**    | `LTAI5t` 开头，约 24 位                |
| `SMS_ACCESS_KEY_SECRET`        | 同一页 → AccessKey Secret 右侧**复制**（只显示一次）  | 字母数字，约 30 位                       |
| `SMS_SIGN_NAME`                | 号码认证服务控制台 →「**赠送签名配置**」→ 你选定的那个**签名名称** | 中文或英文品牌名（**不要**抄签名里的【】）           |
| `SMS_TEMPLATE_CODE`            | 「**赠送模板配置**」→ 你选定的模板的**模板编号**           | 纯数字，形如 `100001`（**不是** `SMS_xxx`） |
| `SMS_TEMPLATE_PARAM_NAME`      | 一般不用动                                   | 默认 `code`；模板变量名不叫 code 时才改        |
| `SMS_TEMPLATE_EXTRA_JSON`      | 模板里还有别的变量时补固定值，例如 `{"min":"5"}`         | 没有额外变量就保持 `{}`                    |
| `SMS_DYPNS_VALID_TIME_SECONDS` | 不用动                                     | 默认 300 秒                          |
| `SMS_DYPNS_INTERVAL_SECONDS`   | 不用动                                     | 默认 60 秒                           |
| `SMS_NOTICE_TEMPLATE_CODE`     | 通道 A 用不到                                | **保持空白**，不要填任何东西                  |

```ini
SMS_PROVIDER=aliyun_dypns          # 固定值：走个人可开通的短信认证通道
SMS_ACCESS_KEY_ID=LTAI5t************        # ① RAM 成功页复制
SMS_ACCESS_KEY_SECRET=************************   # ② 同一页复制（关掉页面就没了）
SMS_SIGN_NAME=恒创联众              # ③ 示例，填「赠送签名配置」里选定的签名名称
SMS_TEMPLATE_CODE=100001           # ④ 示例，填「赠送模板配置」里选定的编号（纯数字）
SMS_TEMPLATE_PARAM_NAME=code       # 一般不用改
SMS_TEMPLATE_EXTRA_JSON={"min":"5"}  # ⚠️ 赠送模板 100001 必填；见下方说明
SMS_DYPNS_VALID_TIME_SECONDS=300   # 验证码有效期（秒），可不动
SMS_DYPNS_INTERVAL_SECONDS=60      # 同号发送间隔（秒），可不动
# 通道 A 不支持通知短信，这一项留空即可
SMS_NOTICE_TEMPLATE_CODE=
```

> ⚠️ **`SMS_TEMPLATE_EXTRA_JSON` 对赠送模板 100001 是必填的。**  
> 该模板正文是「您的验证码是 `${code}`，有效期 `${min}` 分钟，请勿告诉他人。」，  
> 缺了 `min` 会被阿里云拒绝，报 **`isv.INVALID_PARAMETERS　模版变量min内容非法`**。  
> 所以这里要写成 `{"min":"5"}`，其中 `5` 应与 `SMS_CODE_TTL_SECONDS`（默认 300 秒）保持一致。  
> 若你选中的是别的赠送模板，请照控制台里该模板的变量列表补齐。
>
> 抄写注意：值**不要加引号、不要带首尾空格**（Secret 末尾多一个空格就会报 `SignatureDoesNotMatch`）。  
> 更稳的做法是直接跑下面第 ⑥′ 步的 `enable_sms.py`，它替你写这些值并立即实测，抄错会当场报出来。

**⑥′ 更省事的方式：一条命令完成「写配置 + 实测 + 失败回滚」**

不想手改 `.env` 就走这条——它会把上面的值写进 `.env`（先备份为 `.env.bak`），  
立刻真发一条验证码，**失败则自动把 `SMS_PROVIDER` 回滚**，不会让登录接口因凭证错误而报错：

```powershell
cd "E:\cg\Documents\WorkBuddy\电动车识别"
.\.venv\Scripts\python.exe scripts\enable_sms.py --ak-id 你的AK --ak-secret 你的Secret --sign 赠送签名名称 --template 100001 --extra min=5 --phone 18674314014
```

> `--extra min=5` 就是给模板里的 `${min}` 变量赋值（可重复：`--extra min=5 --extra foo=bar`）。  
> 它故意不用 JSON 字符串，因为 `{"min":"5"}` 这种写法在不同 shell 里的引号处理不同，  
> 容易一个能跑一个报错；`KEY=VALUE` 各种终端行为一致。
>
> ⚠️ 命令里带「你的」的都是占位符，必须替换成控制台里的真实值；原样粘贴会被脚本拦下（见下方防呆校验）。  
> 签名名称**含空格时**用双引号包起来：`--sign "中国电信 天翼"`。

通道 B（企业资质、需要通知短信）加两个参数即可：

```powershell
.\.venv\Scripts\python.exe scripts\enable_sms.py --provider aliyun --ak-id 你的AK --ak-secret 你的Secret --sign 湘西州数据局 --template SMS_123456789 --notice-template SMS_987654321 --phone 18674314014
```

不带 `--phone` 时只写配置、不产生短信费用；`--extra` 不传则等价于 `{}`（模板无额外变量时用）。

**防呆校验（脚本会先查再写，不合格不动任何文件）**

| 检查项                       | 拦截条件                                                                 |
| ------------------------- | -------------------------------------------------------------------- |
| `--ak-id` / `--ak-secret` | 含「你的」等占位符字样、含 `*`（打码值）、含中文或空格                                        |
| `--sign`                  | 为空，或仍是「赠送签名名称」「你的…」这类占位符                                             |
| `--template`              | dypns 通道要求**纯数字**（写成 `SMS_xxx` 会提示那是企业通道格式）；企业通道要求形如 `SMS_123456789` |
| `--extra`                 | 缺 `=`（写成 `min:5`）、键为空                                                |
| `--extra-json`            | 不是合法 JSON，或不是 JSON 对象                                                |
| `--phone`                 | 不是 1 开头的 11 位手机号                                                     |

不通过时会逐条打印中文原因并**直接退出，`.env` 与 `.env.bak` 都不生成**。

**⑦ 能力边界（务必知悉）**

- **只能发验证码**：`send_notice()` 会返回失败并记录日志，审核结果通知自动走站内信（该降级逻辑本来就有，不需要改代码）；
- **频控是双层的**：程序内 `SMS_SEND_INTERVAL_SECONDS`（默认 60 秒）+ 接口 `Interval`；同一号码另有天级流控，触发后返回 `BUSINESS_LIMIT_CONTROL`；
- **验证码由本系统生成并自行校验**（不是让阿里云代生成），所以 `SMS_CODE_TTL_SECONDS` 才是真正的有效期，接口的 `ValidTime` 只影响短信文案里「有效期 X 分钟」的表述；
- 短信内容与签名不可自定义，这是免资质的代价。

## 二、域名 + HTTPS 证书（生产必需）

> 为什么必需：手机浏览器只有在 **HTTPS 安全上下文**下才允许调用摄像头与定位。HTTP 下拍照上报在真机上直接不可用。

**本项目域名：`ebikeguard.xyz`** —— 2026-10-10 注册，2027-10-11 到期，实名认证已通过。  
定位是**开发联调 + 演示**；正式对外发布应使用单位备案的 `.gov.cn`（该后缀仅党政机关 / 事业单位可注册）。

### 2.0 域名到手后的下一步（先选路线，再动手）

| 路线            | 做法                                                         | 是否需要 ICP 备案                          | 成本         | 适用              |
| ------------- | ---------------------------------------------------------- | ------------------------------------ | ---------- | --------------- |
| **A 正式上线**    | 大陆节点服务器（ECS / 轻量应用服务器）+ **单位备案**                           | 必须（工信备案 + 公安备案）                      | 服务器月付      | 面向公众正式发布        |
| **B 开发期真机测试** | Cloudflare Tunnel 把 `ebikeguard.xyz` 指到本机 `127.0.0.1:8000` | **不需要**（流量走 Cloudflare 边缘，源站不暴露公网端口） | 0 元        | 现在就要用手机真机拍照测试   |
| **C 独立测试环境**  | 阿里云**中国香港**轻量应用服务器                                         | **不需要工信备案**，仅需公安备案                   | 约 ¥24~30/月 | 想要稳定 443、又不愿等备案 |

**四个硬性条件（别踩空）**

1. **实名认证通过后约 3 天**才能提交备案。官方原文：「域名实名认证、修改/过户完成后，需要约三天时间将实名认证信息入库管局。  
   建议您在实名认证完成后至少等待三天再申请 ICP 备案」。本条**不是**「注册满 3 个月」，两个概念不要混淆。
2. 备案要求域名**距到期日大于 45 天** —— `ebikeguard.xyz` 2027-10-11 到期，满足。
3. 备案前需要**备案服务码**，它来自阿里云大陆节点云产品（ECS / 轻量应用服务器等）  
   —— 所以实际顺序是**先买服务器，再备案**。
4. **本项目不适合走个人备案**。官方规则：个人备案「内容不可涉及企业、行业、交易等」，  
   网站名称须 **3 个及以上汉字**、不得含行业 / 企业 / 产品信息，并禁用「平台 / 资讯 / 社区 / 论坛」等词。  
   本系统是面向公众的电动车违规上报，属行业 / 政务性质 → 应走**单位备案**（湘西州数据局）。

**路线 B 怎么做（最快，今天就能跑起来）**

1. 域名 NS 改为 Cloudflare 的两条 NS（阿里云域名控制台 → DNS 修改 → 修改 DNS 服务器）；
2. Cloudflare 控制台 → Zero Trust → Networks → Tunnels → 创建隧道（免费套餐）；
3. **在服务器上**安装 `cloudflared`（Ubuntu 可用官方 deb 包或 `apt` 源），按页面给出的命令启动连接器  
   —— 本项目服务已经跑在服务器上，所以隧道要装在**服务器**，不是自家电脑；
4. 隧道的「公共主机名」填 `ebikeguard.xyz`，「服务」填 **`http://127.0.0.1:8000`**（直连应用）；
5. 手机/浏览器打开 `https://ebikeguard.xyz`，证书由 Cloudflare 自动签发。

> ⚠️ **第 4 步不要填 `http://127.0.0.1:80`**：nginx 收到的是明文 HTTP，会按 80 段规则返回  
> `301 https://ebikeguard.xyz/...`；而浏览器侧的 HTTPS 已经由 Cloudflare 终止，于是又被转回原点 ——  
> **形成重定向循环**。直连 `:8000` 即可。走隧道期间，nginx 那套（含刚配好的证书）暂不参与；  
> 等备案通过、域名直接解析到大陆服务器时再启用。

> ⚠️ 边界：Cloudflare 官方明确该工具**仅用于本地开发与测试**、禁止用于生产；且未备案域名走境外边缘，  
> 大陆访问速度不稳定。政务正式上线仍须走路线 A。

**⑤ 未备案时的实际可访问性（2026-10-11 实测，供开发期使用）**

把 `www.ebikeguard.xyz` 的 A 记录指向大陆服务器后，从外网实测两个端口的行为**完全不同**：

| 端口                            | 实测结果                                                                                    |
| ----------------------------- | --------------------------------------------------------------------------------------- |
| `https://www.ebikeguard.xyz/` | **`200 OK`**，返回项目登录页（`Server: nginx/1.24.0`）                                            |
| `http://www.ebikeguard.xyz/`  | **`403 Forbidden`**，`Server: Beaver`，页面标题 **「Non-compliance ICP Filing」** —— 阿里云的未备案拦截页 |

也就是说阿里云的拦截目前只作用在 **80 端口**上；443 因流量加密未受影响。

> **两点必须说清**：
>
> 1. **这不等于可以不备案**。ICP 备案是《互联网信息服务管理办法》的强制要求，拦截策略由服务商侧随时可调，  
>    不能把「443 当前能通」当作长期方案；正式对外发布必须走路线 A（单位备案）。
> 2. 在**开发测试期**，手机可以直接打开 **`https://www.ebikeguard.xyz`** 做真机拍照验证 ——  
>    注意**必须显式带上 `https://`**：裸输入域名时浏览器可能先走 http，那时命中的是 403 拦截页，  
>    而 HTTP→HTTPS 的跳转写在 nginx 的 80 段里，公网访问时根本走不到。

### 2.1 操作步骤（路线 A / C 的完整部署步骤）

**① 准备域名并完成 ICP 备案（仅路线 A 需要）**  
大陆节点服务器必须备案。政务系统走**单位备案**：阿里云「ICP 备案」→ 填写主体信息（单位证件、负责人身份证、  
授权书）→ 阿里云初审（1~~2 个工作日，含电话核验）→ 工信部短信核验（24 小时内完成）→  
管局审核（1~~20 个工作日）。备案期间把域名解析到大陆服务器会被阻断，属正常现象。

**② 添加解析（只适用于「已备案的大陆服务器」这条路线）**

⚠️ **走路线 B（Cloudflare Tunnel）就跳过这一步** —— 那条路要先把域名 NS 改到 Cloudflare，  
改完之后阿里云云解析里的记录全部失效，隧道记录由 Cloudflare 自动创建。  
判断当前状态：`ebikeguard.xyz` 的 NS 若仍是 `dns17.hichina.com` / `dns18.hichina.com`，说明还在阿里云，可直接加记录。

「云解析 DNS」→ `ebikeguard.xyz` → 添加记录，逐项这样填：

| 字段   | 填什么                                                                  |
| ---- | -------------------------------------------------------------------- |
| 记录类型 | `A`（把域名指向一个 IPv4 地址）                                                 |
| 主机记录 | `@`（代表 `ebikeguard.xyz` 本身）；要 `www.ebikeguard.xyz` 就再加一条，主机记录填 `www` |
| 解析线路 | `默认`                                                                 |
| 记录值  | 服务器的**公网 IP**（ECS / 轻量实例列表里的「公网 IP」，不是内网 IP、不是 `127.0.0.1`）          |
| TTL  | `10 分钟`（免费版默认值，不用改）                                                  |
| 状态   | 保持「开启」，点「确认」                                                         |

> 面板右下角「云解析个人版 19.9 元/年」是升级推销，本项目用免费版的 10 分钟 TTL 足够，不必购买。  
> ⚠️ 若这台服务器在大陆但**尚未完成备案**，解析过去后该域名的 80 / 443 访问会被阿里云监测系统阻断  
> （用公网 IP 直连通常仍可，但手机端调用摄像头要求 HTTPS，必须有域名 + 有效证书）。

**③ 申请 SSL 证书**  
控制台搜「数字证书管理服务」→ **个人测试证书（原免费证书）** → 领取额度（0 元下单）→ 创建证书 → 填域名 → 完成域名所有权验证 → 几分钟内签发。

> ⚠️ **关于备案前提**：阿里云官方文档把「该域名**已完成 ICP 备案**」写在个人测试证书的使用前提里，  
> 但**实测未备案也能正常申请签发**（2026-10-10，`ebikeguard.xyz` 未备案，成功签出）。以实际能否提交为准；  
> 万一被拦，改走 **Let's Encrypt**（见 2.2 的 certbot，不要求备案）；走路线 B 则由 Cloudflare 自动签发。
>
> 另外三点：
>
> 1. 有效期 **90 天**（不是 1 年），到期前须换新；
> 2. 每人每年 **20 张**额度，当年未用额度 12 月 31 日清零；
> 3. **不支持 `.gov`、`.edu`、`.org`、`.jp`、`.pay`、`.bank`、`.live`、`.nuclear`、`.ru` 等特殊后缀，也不支持通配符**；  
>    官方明确**禁止用于生产环境**（无 SLA 保障）。

**④ 下载证书**  
证书列表 → 下载 → 选择 **Nginx** 格式，得到一个压缩包（内含 `ebikeguard.xyz.pem` 与 `ebikeguard.xyz.key`），  
解压到**本机**任意目录（例如 `E:\微软浏览器下载\SSL证书\`）。

**④′ 从 Windows 上传到服务器**（**在你自己的电脑上执行**，是 PowerShell）

```powershell
cd "E:\微软浏览器下载\SSL证书"
scp .\ebikeguard.xyz.pem .\ebikeguard.xyz.key root@你的服务器公网IP:/tmp/
```

- `scp` 是 Windows 10 / 11 **自带**的 OpenSSH 客户端（无需另外安装）；
- 把 `root` 换成你的登录用户：阿里云轻量默认 `root`，ECS 的 Ubuntu 镜像常是 `ubuntu`（后续 sudo 操作即可）；
- 首次连接会问 `Are you sure you want to continue connecting (yes/no)?` → 输 `yes`，然后输密码；
- **路径含中文时必须加引号**；不放心可先把两个文件复制到英文目录（如 `E:\cert\`）再执行。

**④″ 在服务器上安装证书**（**登录服务器后执行**，是 bash）

```bash
sudo mkdir -p /etc/nginx/ssl
sudo mv /tmp/ebikeguard.xyz.pem /tmp/ebikeguard.xyz.key /etc/nginx/ssl/
sudo chown root:root /etc/nginx/ssl/ebikeguard.xyz.*
sudo chmod 600 /etc/nginx/ssl/ebikeguard.xyz.key
sudo chmod 644 /etc/nginx/ssl/ebikeguard.xyz.pem
ls -l /etc/nginx/ssl/            # 确认两个文件在位，私钥权限应为 -rw-------
sudo openssl x509 -in /etc/nginx/ssl/ebikeguard.xyz.pem -noout -subject -dates
sudo nginx -t                    # 检查配置语法
```

> 用 `mv` 而不是 `cp`：把私钥从 `/tmp` 挪走，避免明文私钥长期留在临时目录。

**⑤ 修改 Nginx 配置**  
`deploy/nginx/ev_audit.conf` **仓库里已按 `ebikeguard.xyz` 填好**，无需再改；若将来换域名，改这三处：

```nginx
server_name ebikeguard.xyz www.ebikeguard.xyz;               # ① 域名（两处：80 与 443 段）
ssl_certificate     /etc/nginx/ssl/ebikeguard.xyz.pem;       # ② 证书
ssl_certificate_key /etc/nginx/ssl/ebikeguard.xyz.key;       # ③ 私钥
```

> `server_name` 写上 `www` 是因为本项目这张证书的 SAN 同时覆盖 `ebikeguard.xyz` 与 `www.ebikeguard.xyz`，  
> 两条都能用同一张证书；若你只想用主域名，也可以只写主域名。
>
> ⚠️ **HTTP/2 的写法必须匹配 nginx 版本**：独立的 `http2 on;` 只在 **nginx ≥ 1.25.1** 存在；  
> Ubuntu 24.04 自带 **1.24.0**，写它会让 `nginx -t` 直接报 `unknown directive "http2"`，  
> 于是 reload 失败、**443 端口根本不监听**（外网表现为连不上 443）。仓库里已改用兼容写法  
> `listen 443 ssl http2;`（1.25.1+ 只会打一条 deprecation 警告，功能正常）。  
> 先用 `nginx -v` 确认版本，再决定用哪种写法。

然后执行部署脚本（**在服务器上执行**；它会自动拷到 `/etc/nginx/conf.d/` 并 reload）：

```bash
sudo bash deploy/scripts/deploy.sh
```

**⑥ 开放端口**  
阿里云「安全组」放行 `80`、`443`；服务器本机防火墙（若有）同步放行。**不要**对外开放 `8000`——Gunicorn 只监听 `127.0.0.1:8000`，由 Nginx 反代。

**⑦ 验证**

```powershell
.\.venv\Scripts\python.exe scripts\check_external.py --domain ebikeguard.xyz
```

会输出 DNS 解析结果、证书主体与**剩余有效天数**（≤30 天告警、≤7 天报错）。

### 2.3 服务器怎么选（本项目口径）

> **单位 / 政务云**资源上，不必为了「将来正式用」在这台个人机器上加配置。

**① 硬性约束（决定能不能备案）**

- 计费方式必须是**包年包月**（按量付费不支持备案服务码）；
- 时长 **≥3 个月**（控制台按「到期剩余 ≥90 天」判断）；
- 地域必须**中国大陆**（港澳台及海外节点不需要工信备案，但也备不了）；
- 单台实例最多申请 **5 个**备案服务码；
- 自检方式：控制台搜索「备案服务码」→ 服务码管理，能列出该实例即可用。

**② 带宽比 CPU / 内存更该先看**

本项目单次最多 **9 张**图、单张上限 **15MB**（`max_images_per_report=9`、`max_image_mb=15`）。  
手机拍摄的典型照片 3~5MB/张，即一次上报约 **27~45MB**，按上限可到 **135MB**。对照带宽：

| 带宽                | 实际吞吐      | 30MB 上传耗时 | 135MB 上传耗时 |
| ----------------- | --------- | --------- | ---------- |
| 3Mbps 固定          | ≈384 KB/s | ≈80 秒     | ≈6 分钟      |
| 5Mbps 固定          | ≈640 KB/s | ≈47 秒     | ≈3.5 分钟    |
| 200Mbps 峰值（轻量，共享） | 视负载       | 数秒        | 数十秒        |

⚠️ Nginx 配置里 `client_body_timeout 120s`（`deploy/nginx/ev_audit.conf`）——**3Mbps 带宽传满 9 张图会被超时掐断**。  
所以带宽选 **5Mbps 以上**，或者先做「前端上传前压缩」再考虑低价小带宽机型。

### 2.4 免费试用实例能不能用（阿里云 1 个月 0 元档）

**能用，但要清楚它的边界。**

- **备不了案**：试用是 1 个月、且非包年包月订单，按 2.3 的备案服务码规则（包月 ≥3 个月、剩余 ≥90 天）  
  不满足，因此**只能当开发 / 联调机**，不能作为正式对外的备案主体资源。
- **镜像必须换掉**：试用页默认勾选的「**宝塔 Linux 面板**」不要用 —— 它会常驻 Nginx / MySQL / PHP  
  等一堆进程，既吃 1 GiB 内存，又会抢占 `80` / `443`，与 `deploy/scripts/deploy.sh`  
  （自管 Nginx + Gunicorn + systemd）冲突。改成**系统镜像 → Ubuntu 22.04 LTS 64 位**。
- **1 GiB 内存的调法**：`deploy/gunicorn/gunicorn.conf.py` 默认 `workers = max(2, min(4, CPU 核数))`，  
  在 1 GiB 机器上建议在 `.env` 里设 **`GUNICORN_WORKERS=1`**（该配置项已支持环境变量覆盖），  
  并加 1~2 GiB swap。内存峰值出现在 Pillow 解码大图时（单张上限 15MB）。
- **200 Mbps 峰值带宽是它最大的优点**：正好补上 2.3 里算出的上传瓶颈，适合真机拍照联调。
- **到期即释放，数据不保留**：不要把唯一副本放在上面；正式数据留在本地或后续迁 OSS。
- **未备案时手机怎么访问它**：走 2.0 的路线 B —— Cloudflare Tunnel 指向这台机器，  
  域名 + HTTPS 一次到位，比指到自家电脑更稳定（不依赖本机开机）。


### 2.5 证书装好后：首次上线部署

**不要单独 `apt install nginx`** —— `deploy/scripts/deploy.sh` 会统一装齐  
（nginx、python3-venv、python3-pip、sqlite3、rsync）并完成全部初始化。手工先装容易出现重复安装或配置路径不一致。

**① 在 Windows 上打包并上传**（**在你自己的电脑上执行**，是 PowerShell；代码已纳入本机 git 版本控制，部署仍走打包上传）

```powershell
cd "E:\cg\Documents\WorkBuddy\电动车识别"
tar -czf "$env:TEMP\ev_audit_src.tar.gz" --exclude=.venv --exclude=data --exclude=__pycache__ --exclude=.pytest_cache --exclude=.env --exclude=.env.bak --exclude=.workbuddy --exclude=test_images --exclude=.git .
scp "$env:TEMP\ev_audit_src.tar.gz" admin@你的服务器公网IP:/tmp/
```

打包结果约 **170 KB**，位于 `C:\Users\cg\AppData\Local\Temp\ev_audit_src.tar.gz`。  
排除项的原因：`.venv`（Windows 版二进制在 Linux 用不了）、`data`（本地测试图片与 SQLite 库）、  
`.env` 与 `.env.bak`（含本机密钥，服务器上应单独生成）、`.workbuddy`（项目记忆，与部署无关）、  
`test_images`（AI 效果验收用的测试照片，只在本机使用，不上传服务器）、`.git`（版本控制元数据，无需上传服务器）。

> **若 `scp` 反复提示 `Permission denied, please try again.`** —— 这**不是密码打错**。  
> 能弹出密码提示，说明 22 端口通、SSH 允许密码认证、用户名也存在，只是**没有可用密码**：  
> 阿里云**实例默认不设登录密码**，控制台的「远程连接 → Workbench 一键连接」是**免密**以 `admin` 身份登录的，  
> 所以「网页终端能进去」与「scp 进不去」并不矛盾。
>
> 两条路，任选其一：
>
> - **免密上传（推荐，不需要密码）**：控制台 → 目标服务器「远程连接」→ Workbench **一键连接** → 立即登录 →  
>   左侧边栏「**文件管理**」→ 进入 `/tmp` → 右键目标目录「**上传**」→ 选本机的 `ev_audit_src.tar.gz`。  
>   一键连接是 `admin` 身份，只能写 `/home/admin` 与 `/tmp`（本流程刚好用 `/tmp`）；  
>   上传依赖服务器已装 `curl`，没有则先执行 `sudo apt-get install -y curl`（Ubuntu）或 `sudo dnf install -y curl`。
> - **先设密码再用 scp**：ECS → 实例 → 更多 → 密码/密钥 → **重置实例密码**（优先选「**在线重置密码**」，  
>   依赖云助手、**不必重启**；选不了或失败时用离线重置，需重启）；  
>   轻量应用服务器 → 服务器 → 更多 → **重置密码**（按控制台提示，通常需重启生效）。  
>   密码要求 **8~30 位**且包含大小写字母、数字、特殊字符。
>
> 另三个常见干扰项：① 输入密码时终端**不显示任何字符**（连星号也没有），这是正常的；  
> ② 输入法必须是**英文半角**，中文输入法打出来的是全角字符，服务器一律拒绝；  
> ③ **服务器登录密码 ≠ 阿里云账号密码**，两者不通用。

**② 在服务器上解包并执行部署脚本**（**登录服务器后执行**，是 bash）

```bash
mkdir -p /tmp/ev_audit_src && tar -xzf /tmp/ev_audit_src.tar.gz -C /tmp/ev_audit_src
sudo bash /tmp/ev_audit_src/deploy/scripts/deploy.sh
```

> 必须在**副本目录**里执行：脚本会把代码 rsync 到 `/opt/ev_audit`；若直接在 `/opt/ev_audit` 内执行，  
> 会退化成自我拷贝。脚本自动完成：装系统依赖 → 建 `evaudit` 系统用户 → rsync 代码 →  
> 建虚拟环境 → 装核心依赖与可选依赖（短信 / OSS SDK）→ 生成 `.env`（随机 `SECRET_KEY`、`DEBUG=false`）→  
> 初始化数据库与种子数据 → 拷 Nginx 配置并 reload → 写入每日备份 cron → **重启 systemd 服务**。  
> 重复部署时 `.env` 与 `data/` 都不会被覆盖或删除，且服务会自动重启（新代码即刻生效）。  
>
> ⚠️ 2026-10-12 之前版本的脚本用 `systemctl enable --now`，**重复部署时不会重启已在运行的服务**，  
> 会表现为「部署完成但跑的还是旧代码」；现已改为 `enable + restart`。若你在旧包上跑过部署，  
> 手动补一条 `sudo systemctl restart ev_audit` 即可（重启是让新代码生效的唯一方式，gunicorn 未开热加载）。

**③ 补服务器上的密钥并重启**

服务器上的 `.env` 由部署脚本新生成（含随机 `SECRET_KEY`、`DEBUG=false`），短信与地图密钥是空的。  
两种补法，任选其一。

> 命令里的 `.venv` 是**带点**的隐藏目录名（项目的虚拟环境），写成 `./venv/`（漏掉那个点）会报  
> `bash: ./venv/bin/python: No such file or directory` —— 这是最容易手敲错的字符，本节所有命令同此。

**方式一：用项目自带脚本写短信（推荐，写完当场实测）**

```bash
cd /opt/ev_audit
sudo -u evaudit ./.venv/bin/python scripts/enable_sms.py --ak-id PASTE_AK_ID --ak-secret PASTE_AK_SECRET --sign 恒创联众 --template 100001 --extra min=5 --phone 18674314014
```

把 `PASTE_AK_ID` / `PASTE_AK_SECRET` **整段替换**成本机 `.env` 里对应的真实值 —— 替换后不能留任何空格。

> ⚠️ 参数值里**不能有空格**：argparse 按空格切分参数，若写成 `本机 .env 里的 AK` 这种带空格的中文占位符，  
> 会直接报 `error: unrecognized arguments: ...`（脚本自己的防呆校验也会拒绝中文与占位符，但它拦不到  
> 「参数已被空格拆散」这一步）。
>
> 若脚本回 `❌ 参数检查未通过，未改动任何文件` 并指出 `--ak-id` 是占位符 —— 那是**防呆校验生效了**，  
> `.env` 一点没被写坏，只需把 `PASTE_AK_ID` / `PASTE_AK_SECRET` 换成真值重跑一次。  
> 两个真值在本机 `.env` 的 `SMS_ACCESS_KEY_ID` / `SMS_ACCESS_KEY_SECRET` 两行，  
> 用 `notepad "E:\cg\Documents\WorkBuddy\电动车识别\.env"` 打开复制即可，不必手抄。

脚本会自动备份 `.env` → 写入 `SMS_PROVIDER` / `AK` / `Secret` / 签名 / 模板 / 额外变量 →  
真发一条验证码 → **失败自动回滚**，不会把登录接口改坏。看到「短信已下发」即成功。  
`--ak-secret` 会留在 shell 历史里，跑完可执行 `history -c` 清理。

高德两项该脚本不管，用下面两条 `sed` 补上（`你的高德Key` 换成本机 `.env` 里那串）：

```bash
sudo sed -i 's|^GEOCODING_PROVIDER=.*|GEOCODING_PROVIDER=amap|; s|^AMAP_KEY=.*|AMAP_KEY=你的高德Key|' /opt/ev_audit/.env
```

## 三、高德地图 Key（建议配置）

### 3.1 操作步骤

1. 打开高德开放平台 <https://lbs.amap.com> → 注册并完成**实名认证**（个人或企业均可）。
2. 控制台 → **应用管理 → 我的应用 → 创建新应用**（名称如「电动车安全上报」）。
3. 在该应用下点 **添加 Key**：
   - Key 名称：随意；
   - **服务平台必须选「Web服务」**（选错会报 `10009`）——本项目是**后端 HTTP 调用** `restapi.amap.com`，  
     选「Web端(JS API)」「iOS」「Android」都不行；
   - 「可用服务」**不用逐项勾选**：服务平台选定「Web服务」后，该 Key 即可调用全部 Web 服务 API  
     （含逆地理编码）。若你在**已有 Key 的「设置」页**里找这个勾选框，会发现它是灰的、点不动 ——  
     这**不是你操作错**，而是高德的规则：**Key 的服务平台一经创建不可修改**，所以「设置」页只用于改  
     名称 / IP 白名单 / 数字签名，服务平台与可用服务仅作展示。真要换平台或服务，只能  
     **删除该 Key 后重新添加**（旧 Key 立即失效，记得同步更新 `.env`）。
4. **「数字签名」保持关闭**。开启后每次请求都要带 `sig`（sha256 签名），本项目后端未实现该逻辑 →  
   会报 `INVALID_USER_SIGN`。若确实需要开启（更安全），需同时给 `app/adapters/geocoding/amap.py`  
   加上签名计算。
5. 复制 Key，填入 `.env`：
   ```ini
   GEOCODING_PROVIDER=amap
   AMAP_KEY=你的32位Key
   ```
6. 重启服务（配置只在进程启动时读取），验证：
   ```powershell
   .\.venv\Scripts\python.exe scripts\check_external.py --probe
   ```
   看到 `✅ 高德逆地理编码  调用成功，示例解析：北京市东城区东华门街道天安门` 即通过。

> **本项目实测记录（2026-10-10）**：`.env` 里的 Key 直连接口返回 `status=1`、`infocode=10000`；  
> 走本项目自己的接口 `POST /api/v1/geo/reverse` 返回  
> `address = 湖南省湘西土家族苗族自治州吉首市镇溪街道人民北路55号中国农业银行(吉首市支行)`。  
> 全程**未勾选任何「可用服务」**，证明 Web 服务 Key 无需该项设置即可调用逆地理编码。

**不装本项目、单独验证 Key 是否可用**（PowerShell，把 KEY 换成你的）：

```powershell
Invoke-RestMethod -Uri "https://restapi.amap.com/v3/geocode/regeo?key=KEY&location=116.481488,39.990464"
```

### 3.2 逆地理编码接口要点（`/v3/geocode/regeo`）

| 项            | 说明                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 请求地址         | `GET https://restapi.amap.com/v3/geocode/regeo`                                                                                            |
| `key`        | 必填，**必须是「Web服务」类型**的 Key                                                                                                                   |
| `location`   | 必填，格式 **`经度,纬度`** —— ⚠️ **经度在前**，与"先说纬度"的直觉相反；最多 6 位小数。本项目按 `f"{longitude:.6f},{latitude:.6f}"` 生成                                         |
| `extensions` | 本项目传 `base`（只要地址）。改成 `all` 会返回周边 POI/道路，响应体大且不省配额，没必要                                                                                      |
| `radius`     | 搜索半径（米），默认 1000。本项目未传，用默认值                                                                                                                 |
| 成功判定         | 返回 `status == "1"`；地址在 `regeocode.formatted_address`，结构化字段在 `regeocode.addressComponent`（省/市/区/街道）                                         |
| 失败           | 看 `info` 与 `infocode`：`10001` Key 无效、`10003` Key 已过期、`10009` Key 与服务平台不符、`10012` 欠费、`10044` 日配额用尽 —— 这些中文提示已写进 `scripts/check_external.py` |

### 3.3 已知风险：坐标系可能不匹配（真机实测后再决定是否处理）

**现状**：前端 `static/upload.js` 用 `navigator.geolocation.getCurrentPosition()` 取经纬度后**直接**送去后端，  
未做任何坐标转换；后端把该坐标直接传给高德 regeo。

**风险**：高德 regeo 要求 **GCJ-02（火星坐标）**，而浏览器 Geolocation 规范上返回 **WGS-84**。  
两者在中国大陆相差约 **百米量级**；且不同浏览器/系统实际返回的坐标系并不统一（业界公认的坑）。  
后果是**只有"地址文字"会偏**（可能偏到相邻街道），**经纬度数值本身不受影响**。

**先实测**：手机打开上报页 → 点「获取当前位置」→ 对比显示的地址与实际位置差多少。  
（电脑端 Chrome 的定位精度本身较差，不要用电脑结果下结论。）

**实测确有明显偏差时，三种修法**：

| 方案                 | 做法                                                                                  | 成本                                        | 副作用                                |
| ------------------ | ----------------------------------------------------------------------------------- | ----------------------------------------- | ---------------------------------- |
| A 后端加转换            | 先调 `/v3/assistant/coordinate/convert?locations=经度,纬度&coordsys=gps` 拿 GCJ-02 再 regeo | 每次多一次 HTTP 调用（仍免费额度内）                     | 若浏览器本就返回 GCJ-02，会被**二次偏移**，同样出错    |
| B 前端改用高德 JS API 定位 | `AMap.Geolocation` 直接返回 GCJ-02                                                      | 需**再申请一个「Web端(JS API)」Key**（并配置安全密钥），前端改造 | 页面引入高德 JS SDK，加载略变重；但坐标最准，还能拿到定位精度 |
| C 维持现状 + 文档标注      | 说明「地址仅供参考，以经纬度与照片为准」                                                                | 0                                         | iOS Safari / Firefox 用户看到的地址可能偏    |

**建议**：先按 C 跑起来并用真机实测；偏差明显再上 B（A 单独用有二次偏移风险，不建议作为唯一方案）。

### 3.4 其他说明

- 免费配额为**每日调用量**限制（个人开发者与企业开发者额度不同，以控制台为准）；本项目仅在用户点击「获取当前位置」时调用一次，用量很小。
- 请求由**后端代理**（`POST /api/v1/geo/reverse`），Key 不出现在前端代码里，避免被盗用。
- 未配置时走 `StubGeocodingProvider`：只存经纬度、不解析地址，地址由上报人手工填写，主流程不受影响。

### 5.4 行为边界与降级策略（重要）

- **结论仅作建议**：保守档策略下「疑似违规」一律进人工复核队列，且**当前未启用自动放行**，模型误判不会造成误裁决；
- **能力边界如实声明**：每条 AI 理由都带 `ENGINE_NOTE`，审核员能看到「本结论由多模态大模型（qwen3-vl-plus）依据照片自动生成，仅作审核参考」；
- **全路径失败降级**：未配 Key、图片读取失败、超时、HTTP 错误、输出无法解析 —— 一律返回 `UNCERTAIN` + 可读中文理由，自动转人工，**绝不中断上报流程**；
- **常见报错对照**：

| 返回                              | 含义             | 处理                                     |
| ------------------------------- | -------------- | -------------------------------------- |
| `HTTP 401 Incorrect API key`    | Key 无效或复制不全    | 重新复制控制台里的 Key（`enable_ai.py --key` 重跑） |
| `HTTP 403 AllocationQuota.FreeTierOnly` | **免费额度已用尽**（已开启「用完即停」） | 到免费额度页关闭该开关改按量付费，或购买额度；未处理期间上报照常接收、AI 初审自动转人工 |
| `HTTP 429` / 限流                 | 触发并发或频率超限      | 无需处理，稍后自动恢复；持续出现则降低并发 |
| `Model not exist`（HTTP 400/404） | 模型名不对或未开通      | 核对 `AI_VL_MODEL`；控制台「模型广场」确认可调用        |
| `data_inspection_failed`        | 图片未通过内容安全检测    | 阿里云对输入有内容审核，罕见；换图或转人工                  |
| 输出无法解析                          | 模型偶尔不按 JSON 输出 | 已自动降级转人工，无需处理                          |

- **隐私提示**：接入后照片会传输至模型服务商（阿里云）。上报页已有「请勿拍摄可识别人脸、车牌」的提示；人脸/车牌打码在 P1 待办中。

## 六、凭证安全守则

1. `.env` 已在 `.gitignore` 中，**不要**提交、不要贴到聊天记录或工单里。
2. 一律使用 **RAM 子账号**，按服务拆分（短信一个、OSS 一个），只授予必需权限；不要用根账号 AccessKey。

5. 阿里云账号开启 MFA；为短信与 OSS 配置**费用告警**（防止 Key 泄露被刷量）。
6. 数据库中的手机号在接口返回时已脱敏（`138****5678`），审核员只看得到脱敏号码。
